## 二、系统边界

- **边界内**：线控制动、线控转向、线控驱动/扭矩控制、主动悬架与姿态控制、底盘域控制器、功能安全与冗余监控链路。
- **边界外**：自动驾驶感知/决策算法、车身内外饰与乘员舱、动力三电与电池能源、车路云协同与交通基础设施；通过标准车载接口交互。

## 三、系统控制结构框图（课堂模板）

模板要素与本系统对象的映射：

| 模板要素 | 本系统对应对象 | 职责与交互内容 |
|---|---|---|
| **Driver** | 自动驾驶域控 AD-ECU；远程接管安全员（M2 模式） | 下发目标车速、横摆/加速度指令与远程遥控指令；接收底盘状态与故障反馈 |
| **System（SOI）** | 线控底盘平台 | Control Algorithm：横/纵/垂向控制策略、冗余监控仲裁、MRM 决策、指令校验；Process Model：制动/转向/驱动/悬架执行链路与整车动力学接口模型 |
| **Vehicle** | L4 整车 | 承载底盘执行机构与乘员；反馈轮速、转角、压力、车身姿态等状态 |
| **Environment** | 道路与交通环境 | 路面附着/坡度/横风、车流行人、天气光照、道路设施、ODD 边界；施加扰动并承受车辆行为影响 |
| **Other System** | 动力三电、车身座舱、高精地图/定位、云控/V2X | 通过 CAN/CAN-FD/车载以太网交换信号、能量与数据 |

### 交互方向

| 链路 | 类型 | 主要信号 / 内容 |
|---|---|---|
| Driver → System | Control Action（红） | 目标车速、目标横摆/横向加速度、目标减速度、远程遥控指令 |
| System → Driver | Feedback（蓝） | 底盘执行状态、传感器/执行器故障、降级与 MRM 状态、可执行性反馈 |
| System → Vehicle | Control Action（红） | 转向角、制动压力/夹紧力、驱动/回收扭矩、悬架刚度与高度作动量 |
| Vehicle → System | Feedback（蓝） | 轮速、转角、制动压力、车身高度与姿态、载荷轴荷状态 |
| System ↔ Other System | Interaction（双向） | 扭矩/能量状态、车身与乘员状态、定位导航、诊断与健康度数据 |
| Environment ↔ Vehicle/System | Interaction | 环境扰动输入、车辆行为输出；V2X/云控/地图数据经相关系统接入 |

## 四、初始系统架构（逻辑视图）

| 编号 | 逻辑子系统 | 主要功能 | 关键接口 / 下属模块 |
|---|---|---|---|
| ARCH-01 | 线控转向 SBW | 自动转向执行、转向冗余备份、路感模拟 | 齿条助力电机、转角/推力传感器、路感电机、备份通道 |
| ARCH-02 | 线控制动 BBW（EMB + 液压冗余） | 电控制动建压、回收协调、驻车与紧急制动 | EMB 卡钳/液压调节器、踏板模拟器、压力传感器、备份制动回路 |
| ARCH-03 | 线控驱动 / 扭矩矢量 | 驱动扭矩分配、牵引力控制、防滑与回收协调 | 电机控制器 MCU、减速器、扭矩分配与 TCS 模块 |
| ARCH-04 | 主动悬架 / 车身姿态 | 减振、侧倾/俯仰抑制、高度与刚度调节 | 空气弹簧/CDC 阀、作动器、高度与姿态传感器 |
| ARCH-05 | 底盘域控制器 Chassis DCU | 策略运行、子系统协调、通信网关、诊断与状态管理 | SoC+MCU、CAN/以太网网关、双源电源、监控诊断单元 |
| ARCH-06 | 功能安全与冗余监控 | 双通道一致性比对、故障检测、降级仲裁、MRM 触发 | 独立监控器、冗余电源/通信链路、安全状态管理软件 |

**架构内数据流**：指令流（智驾域 → DCU 校验仲裁 → 子系统 → 执行机构）；状态流（传感器 → 子系统预处理 → DCU 融合监控 → 反馈智驾域/云控）；安全流（监控器双通道比对 → 异常隔离主链路 → 投入备份 → 降级/MRM）。

## 五、系统需求规格书（SyRS，摘要）

依据 ISO/IEC/IEEE 29148:2018 表 5-1 范例轮廓，承接作业2 StRS 条目：

- **功能需求**：指令接收与合法性校验；运动指令到转向/制动/驱动/悬架作动量的分配；状态采集与闭环反馈；故障/ODD 退出时自主 MRM。
- **可用性需求**：在役可用性 ≥ 99.99%；单点故障不丧失基本运动能力；支持模块级诊断定位与更换。
- **性能需求**：端到端延迟 ≤ 50 ms；横向加速度跟踪误差 ≤ 0.05 g；100→0 km/h 制动距离 ≤ 40 m；jerk ≤ 2.5 m/s³。
- **接口需求**：外部与智驾域、三电、云控标准化接口；内部 DCU—子系统控制/状态/故障接口；安全监控具备独立信号通道。
- **模式与状态**：M1 全自动驾驶 / M2 远程接管 / M3 最小风险 MRM / M4 维保模式。
- **环境条件**：-40℃~+85℃，IP6K9K，满足振动、盐雾与电磁兼容。
- **安保需求**：指令签名校验、拒绝非法指令（UN R155）；停泊灰度 OTA、失败可回滚（UN R156）。
- **验证**：HIL 台架 + 整车场景试验；接口一致性测试；FMEA/FTA、故障注入、渗透测试与型式认证。

## 六、安全需求与安全架构

### 安全需求

| 编号 | 安全需求 | 等级/依据 |
|---|---|---|
| SAFE-01 | 单点失效 200 ms 内进入降级模式，整车仍可安全停车 | ASIL-D · ISO 26262 |
| SAFE-02 | 转向/制动主链路具备备份通道，断电后保留最小转向与制动能力 | ASIL-D · ISO 26262 |
| SAFE-03 | 独立监控器实时比对双通道数据，不一致时隔离主通道并仲裁降级 | 功能安全架构 |
| SAFE-04 | 识别非失效危险（感知局限、操控极限），ODD 内规避或降级 | ISO 21448 SOTIF |
| SAFE-05 | 控制通信防伪造篡改，诊断日志不可未授权修改 | UN R155 |

### 安全架构要点

- **双通道冗余**：供电、通信、计算、执行层主备并行，关键信号双源采集。
- **独立监控**：安全监控器独立于主控制器运行，完成校验、诊断与安全状态仲裁。
- **分级降级**：限制功能 → 限速蠕行 → MRM 靠边停车；备份链路保证最低运动能力。
- **安全状态管理**：定义失效默认状态（EPB 夹紧、转向回正、驱动力切断/保持），保持需求—架构—验证双向可追溯。
- **网络安全分区**：对外接口与内部控制链路隔离，签名校验与访问控制贯穿通信、诊断与升级。
