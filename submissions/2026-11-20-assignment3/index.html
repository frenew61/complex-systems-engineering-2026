1.1 系统目的与范围

本小组所选系统为面向 L4/L5 高级别自动驾驶的线控底盘平台（SOI, System of Interest）：以电信号为指令载体，通过冗余架构实现制动、转向、驱动、悬架等整车运动控制，向上承接自动驾驶域控（智驾域）的规划决策指令，向下驱动各执行部件，是连接「大脑决策」与「车轮执行」的关键执行底座。

  • 系统边界内：线控制动、线控转向、线控驱动/扭矩控制、主动悬架与姿态控制、底盘域控制器、功能安全与冗余监控链路。
  • 系统边界外：自动驾驶感知/决策算法、车身内外饰与乘员舱、动力三电与电池能源、车路云协同与交通基础设施；二者通过标准车载接口交互。

1.2 本作业产出物

  • 系统需求规格书（SyRS）：依据 ISO/IEC/IEEE 29148:2018 表 5-1 范例轮廓，承接作业2 StRS 条目；
  • 初始系统架构：逻辑架构（子系统划分、功能映射与接口）；
  • 系统控制结构框图：按课堂练习模板绘制 Driver / System / Vehicle / Environment / Other System 交互结构；
  • 安全需求与安全架构：功能安全、冗余降级与网络安全设计要点。

二、系统控制结构框图课堂练习模板

下图按课堂练习给定的控制结构模板绘制：Driver（指令发起方）向 System（线控底盘平台，含 Control Algorithm 控制算法与 Process Model 被控对象模型）下发控制作用（Control Action，红色箭头），系统状态经反馈（Feedback，蓝色箭头）回传；System 驱动 Vehicle（整车）并接收整车状态反馈；左侧为 Other System（相关系统），右侧虚线框为 Environment（道路与交通环境）。

System（SOI）线控底盘平台Control Algorithm：底盘域控内的横/纵/垂向控制策略、冗余监控仲裁、MRM 决策与指令校验；Process Model：制动/转向/驱动/悬架执行链路及整车动力学接口模型。
Vehicle搭载本平台的 L4 整车承载底盘执行机构与乘员；向系统反馈轮速、转角、压力、车身姿态等整车状态。

3.1 架构内主要数据流

  • 指令流：智驾域 → DCU 指令校验与仲裁 → 转向/制动/驱动/悬架子系统 → 执行机构。
  • 状态流：各传感器 → 子系统预处理 → DCU 融合与监控 → 反馈智驾域与云控平台。
  • 安全流：监控器独立采集双通道数据 → 一致性比对 → 异常时切断主链路、投入备份、触发降级/MRM。

四、系统需求规格书（SyRS）ISO/IEC/IEEE 29148:2018 表 5-1

SyRS 从技术视角描述系统「将做什么」及其与外部环境的接口，承接作业2 已确认的 StRS 条目；下列需求与第 2 节框图、第 3 节架构相互对应，每条需求均应在第 4 章「验证」中给出对应验证方法。

1. 简介

1.1 系统目的

在 L4/L5 自动驾驶工况下，安全、精确、可冗余地执行整车横/纵/垂向运动控制，作为智驾决策与车轮执行之间的标准执行底座。

1.2 系统范围

覆盖线控转向、制动、驱动、悬架、底盘域控及安全冗余链路；不含感知决策算法、车身内外饰与动力能源本体。

1.3 系统概况

系统环境见第 2 节框图；系统功能为运动指令接收、控制分配、执行驱动、状态反馈与安全降级；用户特征为无在环驾驶员，使用者包括智驾系统、远程安全员与维保人员。

1.4 定义

SBW / BBW / EMB / DCU / MRM / ODD / ASIL / SOTIF / TCS / CDC，缩写同作业2。

2. 参考

  • ISO/IEC/IEEE 29148:2018 需求工程；ISO 26262 道路车辆功能安全；ISO 21448 SOTIF；UN R155/R156；GB/T 40429 驾驶自动化分级。

3. 系统需求

3.1 功能需求

需求编号需求描述对应架构
SyRS-FUNC-01系统应接收智驾域/远程安全员下发的目标车速、横摆与加减速度指令，并完成合法性与物理边界校验。ARCH-05
SyRS-FUNC-02系统应将上层运动指令分配为转向角、制动压力、驱动扭矩与悬架作动量，并协调回收制动与摩擦制动。ARCH-01~04
SyRS-FUNC-03系统应实时采集轮速、转角、压力、姿态等状态并形成闭环反馈。ARCH-05
SyRS-FUNC-04系统应在故障或 ODD 退出时自主执行最小风险动作（减速、靠边停车、双闪、上报）。ARCH-06

3.2 可用性需求

需求编号需求描述
SyRS-AVAIL-01底盘平台在役可用性 ≥ 99.99%；关键控制链路单点故障不应导致整车丧失基本运动能力。
SyRS-AVAIL-02系统应支持不停运情况下的模块级诊断定位与更换，平均维修时间满足维保规程。

3.3 性能需求

需求编号需求描述
SyRS-PERF-01指令到轮端执行输出的端到端延迟 ≤ 50 ms；横向加速度跟踪误差 ≤ 0.05 g，相位滞后 ≤ 30 ms。
SyRS-PERF-02100 km/h→0 紧急制动距离 ≤ 40 m（干燥沥青），制动过程不产生非预期横摆。
SyRS-PERF-03常规工况纵向 jerk ≤ 2.5 m/s³；横向跟踪误差 ≤ 0.2 m，纵向停车距离误差 ≤ 0.1 m。

3.4 接口需求

  • 3.4.1 外部接口：与智驾域提供标准 CAN/CAN-FD/车载以太网接口与信号矩阵；与动力三电交换扭矩/能量状态；与云控平台交换诊断与健康度数据；满足 StRS-BUS-01 的第三方适配要求。
  • 3.4.2 内部接口：DCU 与各子系统之间定义控制指令、状态反馈、故障与使能信号接口；安全监控链路具备独立于主控制链路的信号通道。

3.5 系统运行 / 3.6 模式与状态

模式描述退出条件
M1 全自动驾驶完全由智驾栈控制，无人员在环ODD 退出 / 系统故障 / 急停触发
M2 远程接管云驾舱遥控指令按比例执行远程连接中断 > 3 s
M3 最小风险 MRM自主减速靠边停车、双闪、上报车辆静止且通知完成
M4 维保模式限速 5 km/h，诊断仪可接入退出维保工位

3.7 物理特征 / 3.8 环境条件

执行器与控制器满足车规安装尺寸与布置约束；工作温度 -40℃~+85℃，防护等级 IP6K9K，满足振动、盐雾与电磁兼容要求（承接 StRS-ENV-01）。

3.9 安保（网络安全）需求

  • SyRS-CYBER-01 所有对外控制指令必须签名校验，拒绝未签名/非法指令；满足 UN R155 网络安全管理要求。
  • SyRS-CYBER-02 软件升级须满足 UN R156：停泊状态下灰度升级、失败可回滚（承接 StRS-OTA-01）。

3.10 信息管理 / 3.11 政策法规 / 3.12 生存周期支持 / 3.13 包装运输

故障以标准 DTC 码上报并可追溯到子系统级；满足自动驾驶准入、功能安全与声学提示等法规；支持在役监控、预测性维护与备件供应；零部件按车规包装、运输与仓储条件交付。

五、安全需求与安全架构

线控底盘是 L4 车辆「驾驶员缺失」条件下的最后执行环节，安全为最高优先级。安全需求由功能安全（ISO 26262）、预期功能安全（SOTIF）与网络安全（UN R155）共同构成。

5.1 安全需求

需求编号安全需求描述等级 / 依据
SAFE-01任一单个传感器、执行器或控制器失效时，系统应在 200 ms 内进入降级模式，整车仍可安全停车。ASIL-D · ISO 26262
SAFE-02转向与制动主链路须具备备份通道（机械/液压备份或第二电执行通道），主链路断电后仍可实现最小转向与制动。ASIL-D · ISO 26262
SAFE-03双通道数据须由独立监控器实时比对，不一致时隔离主通道并仲裁降级。功能安全架构要求
SAFE-04应通过场景与边界分析识别非失效导致的危险（感知局限、操控极限），并在 ODD 内规避或降级。ISO 21448 SOTIF
SAFE-05控制通信须防伪造、防篡改；诊断与日志不可被未授权修改。UN R155

5.2 安全架构要点

  • 双通道冗余：主/备控制链路在供电、通信、计算与执行层并行布置，关键信号双源采集。
  • 独立监控：安全监控器独立于主控制器运行，完成一致性校验、故障诊断与安全状态仲裁。
  • 分级降级：故障等级对应不同降级策略——限制功能 → 限速蠕行 → MRM 靠边停车；备份链路保证最低运动能力。
  • 安全状态管理：定义失效后的默认安全状态（EPB 夹紧、转向回正、驱动力切断/保持），并在全生命周期保持需求—架构—验证双向可追溯。
  • 网络安全分区：对外接口与内部控制链路分区隔离，指令签名与访问控制贯穿通信、诊断与升级流程。
追溯关系：本节安全需求由作业2 StRS-SAFE-01/02、StRS-CYBER-01 派生而来，并分配至第 3 节 ARCH-06 安全冗余子系统；后续设计与验证阶段继续向下分解至硬件/软件需求。
